## Documentation Principles

- Describe behavior that exists in the repository.
- Mark experimental and unresolved behavior explicitly.
- Do not present a unit test as proof of browser, PWA, service worker, or device behavior.
- Keep source-specific details inside the relevant adapter or source guide.
- Update documentation in the same pull request as a public contract change.
- Never include credentials, private URLs, cookies, or secret headers.

## Deeper Project Notes

The repository may contain detailed documents for architecture, components, design, schema, testing, or product requirements. These notes can be useful to contributors, but code and verified runtime behavior remain the source of truth when documentation and implementation disagree.
