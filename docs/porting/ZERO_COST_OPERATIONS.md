## Free-tier guard
The optional Turso reader uses the official HTTP pipeline (https://docs.turso.tech/sdk/http/reference), bounded SQL with parameter bindings, a read-only scoped token, immutable snapshot hash check, 2.5s timeout, maximum 2 MiB response, strict 30-minute Redis cache, and shared 1,000 cache-miss admissions/UTC day. On Redis ledger failure or exhausted cap, optional remote catalogue work stops. This cap is a conservative application setting, NOT a guarantee of provider billing consumption. It doesn't meter CDN traffic, platform CPU, Redis commands from other features, or Firebase reads/writes. Official dashboards remain authoritative. Check at 80% and restrict optional operations before provider caps; if account billing is not verified free, do not activate. Vercel Hobby may stop serving on reaching limits, not auto-buy more (https://vercel.com/docs/plans/hobby). No new cron on Vercel.

## Turso import staging (operator-only)
Run `python3 scripts/prepare-turso-import.py stage --snapshot data/canonical/candidate-20261125 --output data/canonical/turso-stage` after permitted-use confirmation. It verifies the original, copies to a fresh uniquely named SQLite file, converts only the copy to WAL and checkpoints it, then writes a checksum-bound import plan. To import, use the official authenticated Turso CLI on the operator machine and the script's `import` command with existing group, actual dashboard storage/write headroom and free database slot inputs. Explicit permitted-use, free-plan and import confirmations are mandatory. Never automatically retry a failed or ambiguous create; inspect the new candidate. No production pointer changes; verify remote manifest/query plans/read-only token before activation. See https://turso.tech/blog/migrating-and-importing-sqlite-to-turso-just-got-easier. Headroom estimates are local guards, not provider billing verification. Do not run unattended imports until actual usage and renewal policy are verified.
